# オンラインのみのファイル

WindowsのOFFLINE / RECALL_ON_OPEN / RECALL_ON_DATA_ACCESS属性で、
未取得・一部未取得の項目を読み込み対象から外す。UNPINNEDやREPARSE_POINTだけでは除外しない。
Dropboxパスの文字列判定は使わない。属性を読み取るだけでダウンロードは要求しない。

Browserの一覧は項目を残し、雲マークとツールチップを表示する。
サムネイルは保存済みメタデータに一致するアプリ内キャッシュだけを利用する。
元ファイルのハッシュ検査、Windows Shell/動画/テキスト生成、書庫ページ数取得、
フォルダ表紙生成は実行しない。オンラインのみのフォルダ内へも自動で潜らない。
Viewerのフォルダ画像一覧とBrowser由来の画像スナップショットから該当画像を除外する。
直接開いた場合は同期アプリで取得後に一覧を更新するよう案内する。

一覧取得後の状態変更に備えてworkerの読み込み直前にも確認する。
クラウド項目はサムネイル生成世代内で未取得として完了し、自動再生成を抑制する。
従来のキャンセル・要求ID・世代照合は維持する。取得後は一覧の更新で再判定する。

属性確認と実際のI/Oは原子的ではない。確認直後の状態変化や、既にOS側で開始済みの
クラウドI/Oを強制中断する仕組みではない。今回実Dropboxや実アプリを起動せず、
合成ファイルと属性差し替えによるoffscreen検査を使用する。実機での再現解消は未確認。

参考: https://learn.microsoft.com/en-us/windows/win32/fileio/file-attribute-constants

## 検査記録

クラウド属性・一覧・画像ソース・キャッシュ・本の切替・翻訳・外部書庫・関連付けの
対象220件が成功。Windows Shell/テキストの対象検査、構文、差分チェックも成功。
大画像ZIPのoffscreen評価はout/cloud-files-navigation.jsonで完了。
広い検査では既存の英語翻訳漏れ2件と旧Viewerクリック操作の検査1件も失敗した。
英語翻訳漏れの対象文字列がHEADにもあることは確認したが、クリック検査の原因は未特定。
全テスト成功という扱いにはしていない。
